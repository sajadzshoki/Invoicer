# نسق (Invoicer)

اپلیکیشن حسابداری فارسی برای کسب‌وکارهای کوچک — راست‌به‌چپ، موبایل‌فرست، با طراحی مدرن و ممتاز.

> **وضعیت: فاز ۴ — ماژول کامل فاکتورها (فروش/خرید/پیش‌فاکتور) روی فونداسیون فاز ۱ تا ۳**

---

## فاز ۴ چه چیزهایی اضافه کرد؟

اولین گردش‌کار مالی کامل اپ — ماژول «فاکتورها»:

- **فهرست فاکتورها** (`/invoices/invoice/list`): تب‌های همه/فروش/خرید/پیش‌فاکتور با شمارنده، جستجو روی شمارهٔ فاکتور/نام طرف حساب/توضیحات (با پشتیبانی ارقام فارسی و لاتین)، فیلتر برگهٔ پایین (نوع تسویه، بازهٔ تاریخ امروز/هفته/ماه/بازه دلخواه، وضعیت ارسال) با چیپ فیلترهای فعال، خلاصهٔ دوره (فروش/خرید این ماه + فاکتورهای تسویه‌نشده) و کارت فاکتور با شماره، نوع، طرف حساب، تاریخ، مبلغ کل، وضعیت پرداخت (رنگ+آیکون+متن)، نوع تسویه و وضعیت ارسال.
- **صدور فاکتور** (`/invoices/add`): انتخاب نوع (فروش/خرید/پیش‌فاکتور)، تاریخ جلالی + ساعت با مقدار پیش‌فرض اکنون، انتخاب طرف حساب در برگه (جستجو، مانده/وضعیت، ساخت طرف حساب جدید و **بازگشت خودکار به جریان فاکتور با حفظ فرم** و انتخاب طرف تازه‌ساخته)، انتخاب پیش‌فرض «مشتری عمومی».
- **اقلام فاکتور**: برگهٔ انتخاب کالا/خدمت با جستجوی نام و بارکد، فیلتر نوع/دسته و «اخیراً استفاده‌شده»؛ هر خط شامل تعداد (مثبت)، قیمت واحد (پیش‌فرض: فروش←قیمت فروش، خرید←قیمت خرید، خدمت←فی — بدون تغییر قیمت خودِ کالا)، تخفیف خط و جمع خط؛ کنترل موجودی برای فاکتور فروش با پیام خطای روشن («موجودی کافی نیست») و در دسترس‌بودن موجودی هنگام ویرایش.
- **تخفیف، مالیات و هزینه‌ها**: تخفیف خط + تخفیف کل (با جلوگیری از تخفیف بیش از مبلغ)، مالیات بر ارزش افزوده با نرخ پیکربندی‌پذیر (پیش‌فرض ۹٪) روی مبلغ پس از تخفیف، هزینه‌های اضافی (حمل/خدمات/سایر) و خلاصهٔ مالی با «مبلغ کل» غالب.
- **انواع تسویه**: نقدی (پرداخت کامل؛ بدون اثر بر مانده)، نسیه (کل مبلغ باقی می‌ماند)، اقساط (مبلغ کل/پرداخت‌شده/باقی‌مانده با اعتبارسنجی؛ فقط باقی‌مانده بر مانده اثر می‌گذارد)، چک (اثر مالی تا تعیین وضعیت چک در فاز بعد اعمال نمی‌شود و پس از ثبت به مسیر `/cheque/add/:invoiceId` هدایت می‌شوید).
- **وضعیت ارسال** (ارسال شده/نشده) و بخش جمع‌شوندهٔ «اطلاعات بیشتر» (توضیحات، یادداشت، امضا، اطلاعات تماس مشتری).
- **پیش‌فاکتور**: هیچ اثر مالی یا انباری ندارد؛ ذخیره/ویرایش و **تبدیل به فاکتور فروش** با اعمال یک‌بارهٔ اثرات.
- **صفحهٔ جزئیات** (`/invoices/invoice/:id`): سند کامل فاکتور (طرف حساب، اقلام، خلاصهٔ مالی، تسویه، ارسال، اطلاعات اختیاری)، منوی بیشتر (ویرایش، کپی فاکتور به‌صورت پیش‌فاکتور، چاپ با استایل اختصاصی، اشتراک‌گذاری با Web Share و فال‌بک کپی متن، حذف با تأیید و هشدار بازگشت اثرات).
- **ویرایش بدون اثر مضاعف**: هنگام ویرایش/حذف فاکتور، حرکت‌های انباری و رکوردهای مالی متصل به آن (با شناسهٔ فاکتور) بازگشت و سپس اثر جدید اعمال می‌شود.

### معماری حسابداری فاز ۴ — تصمیم‌های کلیدی

- **فاکتور منبع حقیقت است**: ماندهٔ طرف حساب و موجودی انبار از رکوردهای متصل به فاکتور مشتق می‌شوند؛ هرگز عددی جداگانه «جمع/کم» نمی‌شود و هیچ اثری دو بار اعمال نمی‌گردد.
- اثر مالی: نسیه/اقساط به‌صورت رکورد فاکتور فروش/خرید (و پیش‌پرداخت جدا) با تگ `invoiceId` در دفتر حساب ثبت می‌شود؛ نقدی و چک رکورد مالی نمی‌سازند.
- اثر انباری: فاکتور فروش ← خروج و فاکتور خرید ← ورود کالا با منبع `INVOICE` و `invoiceId`؛ خدمات اثر انباری ندارند. **ورود/خروج دستی همچنان فقط انباری و بدون اثر مالی است** و با فاکتور ادغام نشده است.
- پیش‌فاکتور هیچ اثری ندارد؛ شمارهٔ فاکتور یکتا (INV-1001 به بعد) و نام/قیمت اقلام در لحظهٔ ثبت روی فاکتور اسنپ‌شات می‌شوند.

### ساختار دادهٔ فاز ۴

```
src/invoices/
├── types.ts    # Invoice, InvoiceItem, ExtraCost, انواع تسویه/وضعیت
├── helpers.ts  # وضعیت و مبالغ مشتق‌شده، جمع‌ها، شمارهٔ بعدی، بازه‌های تاریخ، متن اشتراک
├── seed.ts     # ۳ فروش (نقدی/نسیه/اقساط)، ۲ خرید، ۱ پیش‌فاکتور — سازگار با بذر انبار و دفتر حساب
└── store.tsx   # استور محلی (nasagh:invoices:v1) با ارکستراسیون اثر انباری و مالی
```

## فاز ۳ چه چیزهایی اضافه کرد؟

ماژول «کالاها و خدمات» به‌طور کامل پیاده‌سازی شد:

- **فهرست اقلام** (`/products`): تب‌های **همه / کالاها / خدمات** با شمارنده، جست‌وجو روی **نام و بارکد**، فیلتر نوع/وضعیت موجودی/دسته‌بندی و مرتب‌سازی (جدیدترین، الفبا، قیمت، موجودی) در برگه‌های پایین؛ چیپ فیلترهای فعال و دکمهٔ «حذف همهٔ فیلترها». کارت کالا تصویر، دسته، موجودی با واحد، قیمت فروش و وضعیت موجودی را نشان می‌دهد و کارت خدمت، فی را. حالت‌های خالی مجزا برای «بدون کالا» و «بدون خدمت» و حالت «نتیجه‌ای پیدا نشد» همراه با عبارت جست‌وجو.
- **کالا و خدمت دو موجودیت جداگانه‌اند**: کالا دارای موجودی، واحد، قیمت خرید/فروش، بارکد، نقطهٔ سفارش و حداقل سفارش است؛ خدمت فقط «فی» دارد. هر دو در نام، تصویر، توضیحات، دسته‌بندی و «نمایش در لیست قیمت آنلاین» مشترک‌اند.
- **افزودن** (`/products/add`): نخستین گام **انتخاب نوع** (کالا/خدمت) است و فرم بر اساس نوع به‌صورت پویا تغییر می‌کند؛ در ویرایش، نوع قفل است.
- **فرم کالا**: تصویر، نام\*، توضیحات، بارکد (با اعتبارسنجی یکتایی و دکمهٔ اسکن)، واحد\* با چیپ‌های پیشنهادی، موجودی اولیه (صفر مجاز)، قیمت خرید\*، قیمت فروش\*، نقطهٔ سفارش، نمایش در لیست قیمت آنلاین، دسته‌بندی، حداقل تعداد سفارش.
- **فرم خدمت**: تصویر، نام\*، توضیحات، فی\*، دسته‌بندی، نمایش در لیست قیمت آنلاین — بدون فیلدهای انباری و با فراخوانی بصری که ماهیت «خدمت» را روشن می‌کند.
- **بارکد**: برگهٔ اسکنرِ **نمایشی/موک** با انیمیشن خط اسکن (بدون ادعای دوربین واقعی؛ معماری آماده برای اتصال به اسکنر بومی/وب در آینده) و اعتبارسنجی عددی.
- **انتخاب تصویر**: کلیک/پیش‌نمایش/جایگزینی/حذف با کوچک‌سازی خودکار تصویر؛ در این فاز (موک) تصویر فقط روی همین دستگاه ذخیره می‌شود و ساختار برای آپلود واقعی آماده است.
- **دسته‌بندی‌ها**: مدیریت کامل (افزودن/ویرایش نام/حذف) در برگه؛ دستهٔ در حال استفاده قابل حذف نیست و هشدار می‌گیرد. دسته‌های نمونه: مواد غذایی، پوشاک، لوازم جانبی، خدمات فنی، خدمات مشاوره، سایر.
- **موجودی اولیه**: ساخت کالا با موجودی اولیهٔ مثبت، یک **رکورد «ورود اولیه»** در تاریخچهٔ انبار می‌سازد — کاملاً جدا از فاکتور خرید/فروش مالی، و آمادهٔ مصرف توسط فاکتورها در فازهای بعد.
- **صفحهٔ جزئیات** (`/products/:id`): پروفایل با تصویر، وضعیت موجودی (موجود/رو به اتمام/ناموجود با رنگ+آیکون+متن)، دسته و وضعیت لیست قیمت؛ مشخصات کامل کالا؛ **خلاصهٔ موجودی** (موجودی فعلی، مجموع ورود، مجموع خروج) با هشدار «رو به اتمام»/«ناموجود».
- **تاریخچهٔ حرکات انبار**: هر حرکت نوع (ورود/خروج)، تعداد با واحد، تاریخ جلالی و توضیحات دارد؛ فیلتر همه/ورود/خروج؛ حالت خالی «هنوز حرکتی برای این کالا ثبت نشده است.»
- **ورود/خروج دستی**: برگه با تعداد\* (مثبت؛ خروج نمی‌تواند از موجودی فعلی بیشتر باشد)، تاریخ\* و توضیحات؛ پس از ثبت: به‌روزرسانی موجودی، خلاصه، تاریخچه و توست تأیید.
- **ویرایش** (`/products/add?id=:id`) با پیش‌پر کامل فرم و **حذف با مودال تأیید** + هشدار ویژه برای کالای دارای تاریخچهٔ انبار/موجودی.
- **لیست قیمت آنلاین**: سوییچ فعال/غیرفعال در فرم؛ هنگام فعال‌بودن برای کالا «حداقل تعداد سفارش» گرفته می‌شود؛ نشان «نمایش در لیست قیمت/عدم نمایش» در فهرست و جزئیات. (صفحهٔ عمومی لیست قیمت در فازهای بعد.)
- **حالت‌ها**: اسکلت فهرست و جزئیات، اسکلِت فرم در حال ارسال، خطای اعتبارسنجی درون‌خطی، جست‌وجو/فیلتر بدون نتیجه، حالت خالی تاریخچه، تأیید حذف و بازخورد عملیات ناموفق.

### جداسازی انبار از حسابداری — تصمیم کلیدی معماری

حرکات **ورود/خروج انبار فقط موجودی کالا را تغییر می‌دهند**؛ هیچ اثری روی مانده‌حساب طرف حساب، طلب/بدهی یا درآمد/هزینه ندارند. این حرکات از نظر مفهومی با فاکتورهای واقعی خرید/فروش (فاز بعد) جدا هستند و صرفاً موجودی انبار را منعکس می‌کنند. استور انبار (`src/inventory/store.tsx`) مستقل از استور دفتر حساب (`src/book/store.tsx`) است و این مفاهیم عامدانه ادغام نشده‌اند.

### معماری دادهٔ فاز ۳

```
src/inventory/
├── types.ts    # Product (کالا|خدمت)، StockMovement (ورود|خروج)، ProductCategory
├── helpers.ts  # وضعیت موجودی، قیمت نمایشی، مجموع ورود/خروج
├── seed.ts     # دادهٔ نمونه: ۵ کالا (موجود/رو به اتمام/ناموجود)، ۳ خدمت، ۶ دسته، حرکات انبار
└── store.tsx   # استور محلی با ذخیره در localStorage (کلید nasagh:inventory:v1)
```

قوانین مدل: فیلدهای اختصاصی هر نوع برای نوع دیگر ثبت نمی‌شوند (بدون مقدار بی‌معنی)، بارکد یکتا است، موجودی هرگز منفی نمی‌شود و دسته‌بندی «بدون دسته» مجاز است.

## فاز ۲ شامل چه چیزهایی است؟

ماژول «طرف حساب‌ها» (دفتر حساب):

- **فهرست طرف حساب‌ها** (`/bookAccount`): جست‌وجو روی نام و شمارهٔ تماس، فیلتر وضعیت (همه/بدهکار/بستانکار/تسویه‌شده)، مرتب‌سازی (جدیدترین، الفبا، بیشترین/کمترین مانده)، پاک‌کردن فیلترها، کارت‌های ریسپانسیو با آواتار، ماندهٔ حساب، نشان وضعیت (رنگ + آیکون + متن) و آخرین تراکنش.
- **افزودن طرف حساب** (`/bookAccount/add-customer`): فرم موبایل‌فرست با اعتبارسنجی درون‌خطی (نام الزامی، اعتبارسنجی شمارهٔ تماس)، تاریخ تولد با انتخابگر جلالی، نوار اقدام چسبان، بازخورد موفقیت و ناوبری به صفحهٔ جزئیات.
- **افزودن از مخاطبین**: برگهٔ انتخاب مخاطب با جست‌وجو و دادهٔ نمونه؛ معماری با نقطهٔ اتصال `contactsService` برای اتصال بومی در آینده؛ پیش‌پر کردن خودکار فرم.
- **صفحهٔ جزئیات طرف حساب** (`/bookAccount/:id`): پروفایل (تماس با `tel:`، ویرایش)، خلاصهٔ مالی (مانده به‌عنوان عدد اصلی، طلب، بدهی، مجموع خرید/فروش، سود)، وضعیت بدهکار/بستانکار/تسویه‌شده.
- **پول گرفتم / پول دادم**: برگهٔ فرم تراکنش با ورودی مبلغ (ارقام فارسی و جداکنندهٔ هزارگان)، انتخاب تاریخ جلالی، توضیحات و پیوستِ نشانه‌گذاری‌شده برای فاز بعد؛ به‌روزرسانی آنی مانده و تاریخچه + توست تأیید. «ثبت فاکتور» فقط پیام «در فاز بعدی فعال می‌شود» نشان می‌دهد.
- **تاریخچه حساب**: تایم‌لاین دریافت/پرداخت + فاکتورهای نمایشیِ فازِ بعد، فیلتر (همه/دریافت/پرداخت)، فیلتر بازهٔ زمانی و جست‌وجو در برگه، وضعیت خالی و بدون‌نتیجه.
- **یادداشت‌ها**: افزودن/ویرایش/حذف با تأیید حذف؛ تاریخ خودکار؛ نمایش در تاریخچه.
- **یادآورها**: فرم عنوان/تاریخ/ساعت/توضیحات، ذخیره در حالت محلی، نمایش در صفحهٔ جزئیات (بدون پوش نوتیفیکیشن).
- **ویرایش** (`/bookAccount/add-customer?id=:id`) و **حذف با مودال تأیید** + هشدار مخصوص طرف حساب‌های دارای تاریخچهٔ مالی.
- **حالت‌ها**: بارگذاری فهرست و جزئیات با اسکلت، خطای «پیدا نشد»، جست‌وجوی بدون نتیجه، فرم در حال ارسال.

### معماری دادهٔ فاز ۲

```
src/book/
├── types.ts     # Person, BookAccountTransaction, PartyNote, PartyReminder
├── finance.ts   # محاسبهٔ مانده/وضعیت/خلاصهٔ مالی هر شخص
├── seed.ts      # دادهٔ نمونه + سرویس مخاطبین (نقطهٔ اتصال آینده)
└── store.tsx    # استور محلی با ذخیره در localStorage
```

قرارداد مانده: مثبت = بدهکار (از او طلب داریم)، منفی = بستانکار (به او بدهکاریم).
تراکنش‌های دفتر حساب به شخص تعلق دارند و از مفهوم جداگانهٔ «هزینه‌ها و درآمدها» تفکیک شده‌اند؛ چک‌ها، فاکتورها و گزارش‌ها در فازهای بعد روی همین ساختار سوار می‌شوند.

## فاز ۱ شامل چه چیزهایی است؟

- **پوستهٔ اپلیکیشن**: هدر بالایی (عنوان، بازگشت، اکشن زمینه‌ای، آواتار)، ناوبری پایین موبایل با ۵ مقصد اصلی، و سایدبار معادل در دسکتاپ/تبلت با همان معماری اطلاعات.
- **سیستم طراحی کامل و قابل‌استفادهٔ مجدد**: دکمه‌ها (اصلی/ثانویه/شبحی/مخرب/متنی/آیکونی)، ورودی‌ها (متنی، جست‌وجو، سلکت، تریگر تاریخ، مبلغ، تکست‌اریا)، چک‌باکس/رادیو/سوییچ، تب و سگمنتد کنترل، کارت، آیتم لیست، آواتار، نشان‌ها، باتم‌شیت، مودال، کشو، توست، هشدار، وضعیت خالی/خطا/بارگذاری، اسکلت و تولتیپ.
- **دو تم روشن و تاریک** با طراحی مستقل و ذخیرهٔ انتخاب کاربر.
- **صفحهٔ خانه** به‌عنوان فونداسیون بصری داشبورد؛ اقدام سریع «افزودن طرف حساب» به فرم واقعی فاز ۲ می‌رود.
- **صفحهٔ مرجع سیستم طراحی** در مسیر `/design-system` (قابل دسترس از پانوشت صفحهٔ «بیشتر»).

اتصال به بک‌اند و هر قابلیت مبتنی بر هوش مصنوعی پیاده‌سازی **نشده** است؛ منطق مالی نیز تا فاز ۴ به‌صورت محلی (دفتر حساب، انبار و فاکتورها) پوشش داده شده است.

| --- | --- |
| زبان و جهت | فارسی، کاملاً RTL با خواص منطقی CSS (`inline-start/end`) |
| تایپوگرافی | فونت [وزیرمتن](https://github.com/rastikerdar/vazirmatn) (نسخهٔ متغیر، سلف‌هاست) |
| اعداد | ارقام فارسی، جداکنندهٔ هزارگان «٬»، واحد تومان، قالب فشردهٔ «میلیون/میلیارد»، تقویم جلالی داخلی |
| رنگ | یک رنگ برند (سبز-فیروزه‌ای عمیق)، خنثی‌های ملایم، چهار رنگ معنایی + توکن‌های مالی (درآمد، هزینه، طلب، بدهی، پرداخت‌شده، در انتظار) |
| وضعیت‌ها | رنگ + آیکون + متن؛ هیچ وضعیت فقط با رنگ منتقل نمی‌شود |
| دسترس‌پذیری | فوکوس قابل‌مشاهده، برچسب اجباری دکمه‌های آیکونی، اهداف لمسی ≥ ۴۴ پیکسل |
| ریسپانسیو | ناوبری پایین در موبایل ← سایدبار در ≥۱۰۲۴ پیکسل؛ گرید دو ستونهٔ فهرست در ≥۷۲۰ پیکسل |

## معماری

```
src/
├── styles/             # ژتون‌ها (روشن/تاریک)، پایه، کامپوننت‌ها، پوسته، فاز ۲ (book)، فاز ۳ (inventory) و فاز ۴ (invoices)
├── lib/                # ابزارهای فارسی، تقویم جلالی، شمارهٔ تلفن، تم
├── components/ui/      # کتابخانهٔ کامپوننت‌های سیستم طراحی (فاز ۱)
├── components/party/   # برگه‌ها و فرم‌های اختصاصی طرف حساب‌ها (فاز ۲)
├── components/product/ # اجزای اختصاصی کالاها و خدمات: تصویر، وضعیت موجودی، دسته‌ها، بارکد، ورود/خروج (فاز ۳)
├── components/invoice/ # برگه‌های انتخاب طرف حساب/قلم و خلاصهٔ مالی فاکتور (فاز ۴)
├── book/               # مدل داده، منطق مالی، استور محلی طرف حساب‌ها (فاز ۲)
├── inventory/          # مدل داده و استور محلی کالاها/خدمات/حرکات انبار (فاز ۳)
├── invoices/           # مدل داده، محاسبات و استور محلی فاکتورها (فاز ۴)
├── app/                # پوستهٔ اپ: سایدبار، ناوبری پایین، هدر صفحه، لوگو
└── pages/              # خانه، طرف حساب‌ها، کالاها و خدمات، فهرست/فرم/جزئیات فاکتور، ثبت چک (اتصال فاز بعد)، بیشتر
```

## اجرا

```bash
npm install
npm run dev      # سرور توسعه روی پورت ۵۱۷۳
npm run build    # بیلد تولید
npm run preview  # پیش‌نمایش بیلد تولید
```
